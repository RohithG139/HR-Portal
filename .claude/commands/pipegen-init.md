# /pipegen-init

Interactively create `pipeline.yml` and generate CI/CD pipeline files for an existing repository.

## Usage

```
/pipegen-init [--repo DIR] [--dry-run]
```

**Arguments (`$ARGUMENTS`):**
- `--repo DIR` — path to the target repository (default: `.`)
- `--dry-run` — validate and preview output without writing any files

## What Gets Generated

| Condition | Output |
|-----------|--------|
| Always | `pipeline.yml` (created or updated at `--repo` root) |
| `ci.provider: github-actions` or `both` | `.github/workflows/ci-cd.yml` |
| `ci.provider: jenkins` or `both` | `Jenkinsfile` |
| `artifact.type: docker` and no `Dockerfile` found | `Dockerfile` |

All pipelines enforce:
- **Mandatory automated tests** before any deployment step
- **HITL approval gates** on every environment deployment
- **Zero hardcoded credentials** — CI secret stores only
- **SHA-pinned third-party Actions** — no mutable tags

## Execution Steps

### Step 0 — Parse Arguments

Parse `$ARGUMENTS`. Extract:
- `REPO` = value of `--repo` (default: `.`)
- `DRY_RUN` = `true` if `--dry-run` present, else `false`

### Step 1 — Scan Repository

Read `REPO` for:
- Manifest files: `package.json`, `pom.xml`, `build.gradle`, `requirements.txt`,
  `pyproject.toml`, `*.csproj` — detect language
- Existing `pipeline.yml` — read if present; skip prompts for already-set fields
- Existing `Dockerfile` — note whether Docker generation is needed
- Existing `.github/workflows/ci-cd.yml` or `Jenkinsfile` — warn if overwriting

Report:
```
DETECTED STACK: [node | python | java | dotnet | unknown]
EXISTING PIPELINE CONFIG: [found | not found]
EXISTING DOCKERFILE: [found | not found]
REPO: [path]
```

### Step 2 — Prompt for Missing Required Info

For each required field not found in an existing `pipeline.yml`:

```
AskUserQuestion: "What is the application name? (used in artifact tags, e.g. my-service)"
```

```
AskUserQuestion: "Which CI provider?
Options: github-actions, jenkins, both"
```

```
AskUserQuestion: "What artifact type?
Options: docker, zip, jar"
```

If `artifact.type: docker`:
```
AskUserQuestion: "What is the container registry URL? (e.g. ghcr.io/my-org, 123456789.dkr.ecr.us-east-1.amazonaws.com)"
```

For each environment (at minimum dev + prod):
```
AskUserQuestion: "What is the deployment target for [env]?
Options: docker (SSH host), aws (ECS Fargate), azure (Container Apps)"
```

```
AskUserQuestion: "What is the HTTPS URL for [env]? (e.g. https://dev.myapp.com)"
```

Skip prompts for fields already detected or present in existing `pipeline.yml`.

### Step 3 — Invoke Pipeline Automation Agent

Call `@pipeline-automation-agent` with the full detected context:

```
Create or update pipeline.yml at [REPO]/pipeline.yml with:

Detected language: [DETECTED_LANGUAGE]
User answers: [collected prompt answers]
Existing config: [contents of existing pipeline.yml, or "none"]

MANDATORY:
1. Validate the resulting config — all validation rules must pass before continuing.
2. Report all validation errors if any. Stop if errors > 0.
3. Return the final validated pipeline.yml content and the template selection matrix.
```

If validation fails, report errors and stop. Do not proceed to file generation.

### Step 4 — Invoke devops-docker-architect

Pass the validated config to `@devops-docker-architect`:

```
Generate CI/CD pipeline files from the following validated pipeline.yml:

[validated pipeline.yml content]

Template selection:
[matrix from pipeline-automation-agent]

Reference .claude/templates/devops/ as starting points.

MANDATORY REQUIREMENTS:
1. Begin every generated file with the pipegen header:
   # GENERATED by pipegen — manual edits may be overwritten.
   # Source: pipeline.yml  |  Re-run: /pipegen-init to regenerate.
2. SHA-pin all third-party GitHub Actions to full 40-character commit SHAs.
3. Zero hardcoded credentials — ${{ secrets.NAME }} only.
4. Non-root Docker runtime user.
5. Approval gate for every environment where auto_deploy: false.
6. Same artifact SHA promoted across all environments — no rebuild per env.
7. Smoke test step after every deployment; rollback on failure.
```

If `DRY_RUN = true`: print generated file contents to stdout. Do not write files.

### Step 5 — Verify and Report

After files are written (or previewed in dry-run):

1. Verify no literal secrets: search generated files for credential patterns.
2. Verify approval gates present for `auto_deploy: false` environments.
3. Verify generated file header present in all files.

Report:
```
GENERATED FILES:
  pipeline.yml                         ✓ created / ✓ updated
  .github/workflows/ci-cd.yml          ✓ created / — skipped
  Jenkinsfile                          ✓ created / — skipped
  Dockerfile                           ✓ created / — skipped (existing)

REQUIRED FOLLOW-UP ACTIONS:
  1. Configure repository secrets:
     - [list required secret names from the config]
  2. Create GitHub Environments (if GitHub Actions):
     - [list environment names with auto_deploy: false]
     - Add required reviewers: GitHub → Settings → Environments → [name] → Required reviewers
  3. Commit generated files on a branch and open a pull request.
     Do NOT merge until Stage 1 CI passes on the PR.
```

## Examples

```bash
# Init current directory (interactive)
/pipegen-init

# Init a specific repo path
/pipegen-init --repo /path/to/my-service

# Preview without writing files
/pipegen-init --repo . --dry-run
```
